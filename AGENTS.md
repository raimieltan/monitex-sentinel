# Project Sentinel

Miniature real-time alarm monitoring system. Take-home assessment — prioritize
a focused, explainable MVP over breadth.

## Architecture

```
apps/simulator (Python)  --ws://localhost:8765-->  apps/api (Node/Express)
apps/video-worker (Python, not yet built)  -----^        |
                                                           v
                                                    PostgreSQL (Prisma)
                                                           |
                                                     BullMQ (Redis)
                                                           |
                                                  AI triage worker (OpenAI,
                                                  falls back to a stub
                                                  provider with no API key)
                                                           |
                                                    Socket.IO -> apps/web
```

Pipeline (see `apps/api/src/services/ingestion.ts` and
`apps/api/src/workers/triageWorker.ts`): validate -> persist immediately ->
enqueue triage job -> broadcast `event:new` -> (async, in the worker) AI
triage -> update DB -> broadcast `event:updated`. The LLM is never called
inline in the WebSocket handler — bursts and slow AI must not block
ingestion.

## Services & ports

| Service    | Path                | Port |
|------------|----------------------|------|
| web        | `apps/web`           | 3000 |
| api        | `apps/api`           | 4000 |
| simulator  | `apps/simulator`     | 8765 (WebSocket) |
| PostgreSQL | docker-compose       | 5433 (mapped, not 5432 — avoids conflicts with a native Postgres install) |
| Redis      | docker-compose       | 6379 |

## Running locally

```bash
docker-compose up -d                       # Postgres + Redis
yarn workspace api dev                     # API on :4000
apps/simulator/.venv/bin/python apps/simulator/stream.py   # feeds ws://localhost:8765
yarn dev:web                               # dashboard on :3000
```

`apps/api/.env` holds config (`DATABASE_URL`, `REDIS_URL`, `SIMULATOR_WS_URL`,
`OPENAI_API_KEY`, ...). See `apps/api/.env.example`.

## Conventions

- **Yarn 1.x only.** Do not use npm or pnpm.
- Prisma 7 requires an explicit driver adapter (`@prisma/adapter-pg`) — see
  `apps/api/src/lib/prisma.ts`. Don't remove it or the client won't connect.
- `apps/api` is an ESM package (`"type": "module"`) with strict TypeScript
  and `verbatimModuleSyntax` — use `import type` for type-only imports and
  `.js` extensions on relative imports (required by `nodenext`).
- Keep files small with clear service boundaries (`config/`, `lib/`,
  `schemas/`, `services/`, `queues/`, `workers/`, `routes/`) — this is meant
  to be explained live in an interview, not clever.
- Incoming events are untrusted: missing/low-confidence fields are normal,
  not exceptional. Validation failures are logged and dropped, never thrown
  uncaught — one bad event must not take down ingestion.
- `apps/web/AGENTS.md` is auto-generated by `next dev` — don't hand-edit it.
